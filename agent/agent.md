# TreeChat — Agent Instructions

> 이 문서는 TreeChat 프로젝트에서 작업하는 코딩 에이전트(Codex, Claude Code 등)의 공통 작업 지침이다.
> **현재 대화에서 확인된 제품 방향**과 **미확정 사항**을 구분한다. 이 문서에 없는 기술 결정이나 기능은 확정 요구사항으로 간주하지 않는다.

## 1. 프로젝트 개요

TreeChat은 **기존 ChatGPT 웹사이트에 기능을 추가하는 브라우저 확장 프로그램**이다.

핵심 가치는 대화를 트리 형태로 분기·정리하고, 필요에 따라 특정 대화에 사용할 맥락(Context)을 선택적으로 구성하는 것이다. 일반적인 질문 사용자는 간단하게 사용할 수 있어야 하고, 문서 작성·개발·자료 조사 등 복잡한 작업을 수행하는 사용자에게는 고급 맥락 관리 기능을 제공하는 방향을 지향한다.

**중요:** 별도의 챗봇 웹사이트를 새로 디자인하는 프로젝트가 아니다. 사용자가 확장 프로그램을 활성화한 상태로 `chatgpt.com`에 접속하면, **ChatGPT의 기존 DOM·화면 구조와 기본 사용 흐름을 최대한 보존하면서** 필요한 버튼·패널 등 최소한의 UI를 추가한다.

## 2. 제품 원칙 (우선순위)

1. **트리형 대화 관리가 주기능이다.** Context 노드 및 다른 고급 기능은 이를 보완한다.
2. **기존 ChatGPT 경험을 유지한다.** 불필요한 화면 재구성이나 독립형 인터페이스를 만들지 않는다.
3. **기본 사용은 간단하게, 고급 기능은 선택적으로 제공한다.** 초보자에게 복잡한 옵션을 강제하지 않는다.
4. **대화의 분기·탐색·재사용을 쉽게 만든다.** 긴 대화에서 특정 주제로 돌아가거나 다른 접근을 시도하는 일이 쉬워야 한다.
5. **데이터 취급은 신중하게 설계한다.** 사용자의 대화 내용을 별도 저장·수집하는 기능은 신뢰·개인정보 문제를 고려하며, 명시적 결정 없이 외부 서버 업로드를 전제하지 않는다.

## 3. 핵심 기능

### 3.1 트리형 대화 분기 및 관리 — 핵심

- 대화를 하나의 긴 선형 기록에만 묶지 않고, 특정 지점에서 여러 갈래로 분기할 수 있게 한다.
- 분기 관계를 **부모–자식 노드 구조**로 표현한다.
- 파일 탐색기처럼 **폴더 안의 폴더를 펼치는 계층형 리스트**를 기본 탐색 방식으로 고려한다. Windows/Linux 파일 탐색기의 계층적 사용 경험을 참고하되 OS UI를 그대로 복제할 필요는 없다.
- 사용자는 대화/분기 목록을 탐색하고 **검색**할 수 있어야 한다.
- 트리 구조가 실제 대화 내용 및 원래 분기 지점과 일치하도록 관리한다.

### 3.2 Context 노드 — 확장 기능

- 사용자가 이전 대화나 작업 정보 가운데 **현재 대화에 필요한 맥락만 선택해 연결**할 수 있도록 한다.
- 무관한 과거 대화를 통째로 가져오는 대신 필요한 정보를 명시적으로 선별하는 경험을 목표로 한다.
- 개발, 문서 작성, 자료 조사처럼 장시간 이어지는 작업을 주요 활용 예로 고려한다.
- Context 노드의 저장 형태, 연결 단위, 적용 시점, 토큰 처리 방법 및 모델 입력 방식은 **미확정**이다. ChatGPT가 실제로 해당 맥락을 전달받았는지 확인할 수 없는 상황에서 전달 성공을 표시하지 않는다.

### 3.3 검색 및 탐색

- 대화 트리의 노드나 분기를 빠르게 찾을 수 있는 검색 기능을 고려한다.
- 검색 범위(제목만/본문 포함), 인덱싱 방식, 결과의 정렬 및 하이라이팅은 설계 단계에서 정한다.

## 4. UX/UI 제약

- **대상 화면:** `chatgpt.com`의 기존 대화 UI.
- **접근법:** 기존 DOM 및 기본 입력/응답/사이드바 기능을 가능한 한 유지하고 필요한 컨트롤만 추가한다.
- **정보 구조:** 트리는 계층형 리스트 중심으로 구성하되, 필요한 경우 접기/펼치기·검색·선택 기능을 제공한다.
- **기능 노출:** 일반 사용자는 기존 채팅을 방해받지 않아야 한다. 복잡한 Context 관리 기능은 필요한 경우에만 노출한다.
- **호환성:** 브라우저 확장 프로그램의 삽입 UI가 ChatGPT의 기본 동작·접근성·키보드 조작·반응형 레이아웃을 손상시키지 않도록 한다.
- **절대 피할 것:** ChatGPT 전체를 대체하는 화면, 확장 프로그램의 목적과 무관한 대규모 UI 개편, 검증되지 않은 ChatGPT DOM 구조에 대한 확정적 가정.

## 5. 검토 중인 개선·확장 아이디어 (확정 요구사항 아님)

아래는 사용자 관점의 불편과 확장 가능성으로 논의된 항목이다. 명시적인 승인 없이 필수 개발 범위에 포함하지 않는다.

- 다른 AI 제공사의 모델·서비스와의 호환성.
- 고급 사용자를 위한 세밀한 작업·맥락 제어.
- 대화별로 Skill을 켜고 끄는 기능.
- 대화 기록의 저장·동기화·복원 정책.
- 기존 유사 확장 프로그램(예: ChatTree) 대비 차별화 전략.

경쟁 제품의 기능은 직접 확인하기 전까지 사실로 단정하지 않는다.

## 6. 데이터와 개인정보 설계 원칙

- 대화 내용에는 민감한 정보가 포함될 수 있으므로 수집·저장·전송 범위를 최소화한다.
- 구현 이전에 **어떤 데이터를, 왜, 어디에, 얼마나 저장하는지**를 구분한다.
- 로컬 저장 방식과 서버 저장 방식의 장단점, 동기화 필요 여부, 사용자 통제 수단을 비교한다.
- 사용자 동의 없는 외부 전송이나 불필요한 데이터 수집을 기본값으로 채택하지 않는다.
- ChatGPT가 제공하지 않는 공식 API나 내부 데이터를 사용할 수 있다고 가정하지 않는다.
- 브라우저 확장 프로그램의 권한은 가능한 최소 범위로 제한한다.

## 7. 기술적 검증이 필요한 사항

**아래는 현재 확정되지 않았으며, 구현 전 조사·검증 대상이다.**

1. ChatGPT 웹사이트에서 분기 시점과 대화 구조를 안정적으로 식별할 수 있는지.
2. 페이지 탐색·대화 전환·동적 DOM 업데이트 환경에서 확장 UI를 어떻게 유지할지.
3. 원본 대화와 확장 프로그램의 트리 데이터를 어떤 식별자로 연결할지.
4. Context 노드 정보를 실제 모델에 주입할 수 있는 경로와 제약이 무엇인지.
5. 저장소(브라우저 로컬 저장소/IndexedDB/선택적 서버)와 동기화 정책.
6. ChatGPT UI 변경 시 기능이 깨지는 문제를 어떻게 탐지하고 대응할지.
7. 대화별 Skill 제어 및 타사 모델 호환성이 실현 가능한 범위.

검증 전에는 **가능하다고 단정하거나 가짜 성공 상태를 구현하지 않는다.**

## 8. 에이전트 작업 규칙

1. **기존 코드 우선 파악:** 작업 전에 프로젝트 구조, README, 관련 설계 문서, 현재 구현과 테스트를 확인한다. 이미 구현된 기능을 임의로 갈아엎지 않는다.
2. **요구사항과 가정 구분:** 확정된 기능, 제안 사항, 기술적 가정을 분리해 기록한다.
3. **작은 단위로 구현:** 한 번에 대규모 재설계하지 말고, 작게 변경하고 동작을 검증한다.
4. **기본 UI 보존:** 기존 ChatGPT DOM 변경은 꼭 필요한 범위로 제한한다. 가능하면 확장 프로그램이 소유한 요소만 생성·관리한다.
5. **데이터 안전:** 마이그레이션·삭제·동기화 관련 변경 시 기존 데이터 손실 가능성을 먼저 점검한다.
6. **증거 기반 보고:** 실행하지 않은 테스트는 통과했다고 쓰지 않는다. 확인한 동작과 확인하지 못한 동작을 분리한다.
7. **범위 확대 금지:** 요청받지 않은 부가 기능이나 기술 스택 전환을 임의로 수행하지 않는다.
8. **보안:** API 키, 인증 토큰, 계정 식별 정보, 사용자의 실제 대화 내용을 로그·예제·커밋에 포함하지 않는다.

## 9. 작업 종료 시 보고 형식

모든 주요 작업의 결과를 다음 형식으로 간결하게 보고한다.

```md
## 작업 내용
- 실제 변경 사항

## 변경 파일
- 파일 경로와 역할

## 검증 결과
- 실행한 명령 및 테스트 결과
- 직접 확인하지 못한 사항

## 남은 문제 / 의사결정 필요 사항
- 미완료 작업
- 요구사항이 확정되지 않은 부분
```
